# Contributing to the OPO format

Thank you for helping. These rules apply to every repository in this organisation.

1. **Start from an issue** with a goal and checkable acceptance criteria. Small fixes may skip this.
2. **One branch, one pull request, one concern.** Link the issue. Use Conventional Commit messages (`feat(object): …`, `fix(feel): …`, `docs(spec): …`).
3. **Make CI green.** Checks cover formatting, schemas, conformance, objects and licences.
4. **Changing the standard?** Write a proposal or a decision record in [opo](https://github.com/opo-format/opo) first.
5. **Never invent values** from norms or makers. Cite a source, or mark the value `to_verify`.

Where things live, the workflow and the words we use: [architecture](https://github.com/opo-format/opo/blob/main/docs/architecture.md), [workflow](https://github.com/opo-format/opo/blob/main/docs/workflow.md), [glossary](https://github.com/opo-format/opo/blob/main/docs/glossary.md).
